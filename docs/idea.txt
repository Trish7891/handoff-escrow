Handoff is escrow and proof-of-work settlement for agent labour. An agent can find work and do work today, but it cannot reliably get paid for it: the buyer must trust the artifact is real, the worker must trust the money exists. Handoff makes the payment condition explicit before money moves, mechanical at delivery, and auditable afterwards.

A buyer posts terms — budget, deadline, machine-checkable acceptance criteria — and hashes them. The budget is escrowed. Workers bid; the buyer assigns one at a price below budget and the difference returns immediately. The worker submits an artifact plus its hash. Criteria are checked by code (file exists, JSON keys, regex, word cap, a command that must exit zero, artifact hash). Passing releases the price minus a fee capped at 5%. Failing refunds the buyer. A padded but substantially correct delivery can be disputed, and an arbiter's published rule splits the escrow, with the rule, the split and the evidence hash written to the same ledger.

How NEAR fits: the job is the account. contracts/handoff is a near-sdk 5 contract where the escrowed balance lives on the contract account itself — no maps, no iteration — and a buyer's terms cannot be edited out from under a worker. Its transition table is mirrored one-to-one by the Python state machine, and a parity test parses the Rust source and fails if they drift. Payouts are NEAR account ids, spendable wherever NEAR Intents reaches. The demo runs the same machine offline so judges can reproduce every outcome without a wallet.

Every event is appended to a hash chain: edit a past amount and verification stops there. python3 -m handoff demo runs three jobs end to end — paid, refunded, split — and renders an offline HTML report. 38 Python tests, 7 contract tests, standard library only.
